# v0.5.0 升级计划：真实优先

目标：让深南大道沿线的场景尽量贴近真实。凡是有数据来源的，优先于估算和美术调整；地标被真实建筑或行道树挡住也接受。

本版本只改现有路线沿线，不扩大场景范围（扩大见文末“不在本版本范围”）。

## 现状基线（v0.4.3）

| 项目 | 现状 | 问题 |
|---|---|---|
| 建筑总数 | 1,624 栋（`public/data/buildings.json`）+ 49 个 3D Warehouse 模型 | — |
| 高度来源 | OSM `height` 224 栋（14%），OSM 楼层数 × 3.2 m 743 栋（46%），按片区和占地面积随机估算 657 栋（40%） | 四成高度是随机的 |
| 虚构建筑（管线） | 204 栋程序化方块楼（`procedural_fill`，负 id） | 位置、形状、高度都是编的 |
| 虚构建筑（运行时） | `src/city/buildings/index.ts` 的“补街墙”：每 100 m 一段，路边约 170 m 内没有楼就补方块楼；两侧共 322 段里有 134 段会触发 | 不避开公园、水面、广场，可能把真实空地填满 |
| 视廊压低 | 4 条视廊（`scripts/city_config.json` 的 `viewCorridors`），有高度数据的 OSM 建筑里 39 栋比真实矮 8 m 以上（例：深铁置业大厦 269 → 19 m，安信金融大厦 182 → 91 m），另有部分被直接删除；视廊内的行道树被压低、广告牌和方块楼避开 | 改变了真实城市 |
| 地标雾效 | 远景地标的雾只有正常的 20%（`CONFIG.city.landmarkFogScale = 0.2`） | 平安金融中心等在远处比真实更清楚 |
| 道路横断面 | 主路 4 车道 × 3.5 m（行车区宽度和碰撞边界不变）；对向车道位置取自 OSM；路边是一套固定宽度的带状结构（路缘 0.3、绿化 3、自行车道 2.5、人行道 8.9、草地 16 m，`SIDE`），两侧镜像 | 没有辅路、侧分带、人行天桥、公交站、地铁口；横向街道只画 70 m |

## 步骤

按顺序做。前一步会改变后一步的输入：先去掉视廊压低，后面接入的真实高度才不会又被压低；先有 CMAB 高度，Overture 新补进来的建筑才有高度可用。每一步完成后单独提交，便于对比和回退。

### 第 0 步：建立对比基线

- 选 10 个固定机位：科技园、沙河东路、世界之窗、华侨城、竹子林、车公庙、香蜜湖、新洲路、平安金融中心脚下、市民中心冲线，加上原来 4 条视廊的起点。白天、日落各截一张。
- 记录每帧 draw call、三角面数和帧率，作为性能基线（v0.4.0 实测为 draw call 205–251，三角面 0.92–1.07 M，60 FPS）。
- 每一步完成后用同一组机位重拍，结果放进 `docs/images/`，供 versions.md 前后对比用。

### 第 1 步：取消视廊压低

**改动**
- `scripts/city_config.json`：`viewCorridors` 改为 `[]`。`apply_view_corridors` 遇到空列表会直接返回，`route.json` 里不再有 `clearZones`。相关代码先保留，需要时可以恢复。
- 以下变化随 `clearZones` 消失自动生效，不用改代码，但要逐项核对：
  - 被压低或删除的真实建筑恢复原高度（`scripts/build_city_data.py` 的 `apply_view_corridors`）。
  - 之前因“挡住地标视线”被跳过的 3D Warehouse 模型会被放置。管线日志里的 `[models] skip ... blocks the view` 行会消失，这些模型要逐个检查放置效果。
  - 行道树不再压低（`src/city/props/treeSight.ts`）。
  - 路边广告牌（`src/city/props/index.ts`）和运行时方块楼（`src/city/buildings/index.ts`）不再避让视廊。
- `landmarkFogScale`：改为 1，地标和其他建筑用相同的雾。如果试玩觉得远景太灰，再单独讨论。

**保留不改**
- APEC 大屏的选址规则仍然“不挡地标视线”（`src/city/screens/pylons.ts` 的 `landmarkBack*`）。大屏是我们自己加的道具，不属于真实城市，挡住地标没有意义。
- 世界之窗埃菲尔铁塔继续用手工金色版。

**验收**
- 管线日志里 `[view]` 不再报告压低或删除。
- 之前那 39 栋楼的高度与 OSM 数据一致。
- 原视廊机位重拍，记录哪些地标在哪一段被挡、挡了多少，写进 CHANGELOG（这是有意的结果，不是问题）。
- versions.md “尚未解决”里“地标被行道树挡住”一条删除。

### 第 2 步：接入 CMAB 建筑高度

数据：[CMAB 中国多属性建筑数据集](https://data.mendeley.com/datasets/b4t2wxhn2y/5)，每栋建筑带高度、功能、年代、质量等属性，许可 CC BY 4.0（Mendeley 页面已确认）。

**2a. 高度**
- 下载：Mendeley 上的 `CMAB_origin.rar`（7.92 GB，全国数据打包成一个文件，不用登录，脚本可以直接下载）。Figshare 的处理版拒绝脚本访问，不用它。
- 解压出深圳所在的 shapefile，只保留当前 OSM 范围内的建筑，存到 `data-raw/cmab/`（不入库），下载和裁剪步骤补进 `data-raw/download.sh`。解压 rar 需要先装 `sevenzip`（`brew install sevenzip`）。
- `scripts/build_city_data.py` 新增 `load_cmab()`：读取裁剪后的 CMAB 多边形，用同一套局部投影（`Proj`）转换，建 STRtree 索引。字段含义见压缩包里的 `Metadata.doc`。
- 匹配：对每栋 OSM 建筑，找重叠的 CMAB 多边形。重叠面积超过 OSM 轮廓 30%，或 CMAB 多边形的形心落在 OSM 轮廓内，就算匹配。匹配到多个时，取重叠面积最大的那个的高度。现有的 IoU 工具函数可以直接复用。
- 先校准，再定优先级：
  - 在有 OSM `height` 的 224 栋上，算 CMAB 高度的误差中位数和整体偏差。
  - 在有楼层数的 743 栋上，比较 CMAB 和“楼层数 × 3.2 m”谁更接近，按高度分段看（< 30 m、30–100 m、> 100 m）。
  - 默认优先级：OSM `height` > OSM 楼层数 > CMAB > 片区估算。如果校准显示 CMAB 在某个高度段明显比楼层数推算准，那一段就让 CMAB 优先。
- `buildings.json` 的 `heightSources` 增加 `cmab` 一类；`docs/osm-coverage.md` 的高度来源表同步更新。

**2b. 按功能和年代选立面（可选，2a 完成后再做）**
- `buildings.json` 每栋楼增加 `use` 字段（办公、住宅、商业、公共、工业），有年代的加 `age`。
- `src/city/buildings/index.ts` 里的 `styleFor(zone, h, seed)` 目前只按片区和高度随机选立面，改成先看 `use` 和 `age`：办公楼用玻璃幕墙，九十年代住宅用瓷砖立面，工业用低矮厂房；没有数据时退回现有逻辑。

**验收**
- 估算高度的占比从 40% 降到 10% 以下（不算补的方块楼）。
- 抽查 10 栋知名建筑，高度与公开资料的误差在 10% 以内。
- 天际线截图与真实照片对比，没有明显不合理的尖峰或塌陷。

**风险**
- CMAB 的轮廓是从卫星图识别的屋顶，高楼会因拍摄角度整体偏移几米到十几米，所以匹配用重叠比例，不用严格的 IoU。
- CMAB 的高度是机器学习推算的，个别建筑可能偏差很大。校准结果写进 CHANGELOG。

### 第 3 步：用 Overture 轮廓替换虚构建筑

数据：[Overture Maps 建筑](https://docs.overturemaps.org/guides/buildings/)，先在 `.venv` 里装 `overturemaps`，再用 `overturemaps download --bbox=113.90,22.50,114.12,22.585 -f geoparquet --type=building` 下载，放在 `data-raw/overture/`。许可是 ODbL，与 OSM 相同。

**改动**
- 只取 `sources` 里不是 OpenStreetMap 的要素，也就是机器学习识别的屋顶轮廓。OSM 部分我们已经直接读了，而且 Overture 用的 OSM 快照日期可能不同。
- 合并规则：Overture 轮廓和任何 OSM 建筑都不重叠（重叠面积 < 20%），才作为新建筑加入。之后走 `build_buildings` 现有的筛选：不压在道路走廊上、不进入公园、水面、广场，面积 ≥ `minArea`。新建筑记为 `src: "overture"`。
- 高度来源顺序：Overture 自带 `height` > CMAB 匹配 > 片区估算。
- 重新跑 `coverage_report`，比较每 250 m 一段的建筑覆盖率中位数（现在 13%）和低于 6% 的段落。
- 管线方块楼：Overture 加入后再看覆盖率。如果剩下的空地基本都是真实的空地（公园、施工地、地铁车辆段），就把 `procedural.enabled` 设为 `false`，彻底不补。
- 运行时补街墙：在 `CONFIG.city` 加一个开关，有 `buildings.json` 时默认关闭。路边真实存在的空地就应该是空的。

**验收**
- 虚构建筑（管线方块楼加运行时补楼）降到 0，或者只剩少数几栋，并在 CHANGELOG 里逐处说明理由。
- 覆盖率中位数明显上升；原来覆盖率很低、但现实中有楼的路段（比如华侨城东的住宅区）有了真实轮廓。
- 世界之窗、竹子林地铁车辆段、香蜜湖施工地这些真实空地保持空着。
- `docs/asset-credits.md` 增加 Overture 的署名。游戏内的数据署名同步加上 Overture。

### 第 4 步：深南大道的真实横断面

原则：只改看得见的部分，行车区宽度（4 车道）和碰撞边界不变，所以驾驶手感、圈速、撞墙判定都不受影响。

**4a. 管线：提取辅路和路边设施**
- 辅路：`parse_osm` 已经把所有可行驶道路读进缓存，辅路（如 `深南大道辅路`）现在只是被路线和路口识别排除了。仿照 `opposite_orig`，把每条腿两侧的辅路投影到路线上，输出到 `route.json`：
  - `sideRoadRight`、`sideRoadLeft`：每个采样点辅路中心线的横向偏移，没有辅路的地方为 `null`。
  - 辅路车道数：取 OSM `lanes`，没有就按 2 条。
- 路边设施：`parse_osm` 增加读取以下要素，`CACHE_VERSION` 加 1：
  - 人行天桥：`highway=footway` 且 `bridge=yes`，并且跨过路线的。
  - 公交站：`highway=bus_stop` 或 `public_transport=platform`。
  - 地铁出入口：`railway=subway_entrance`。

  这些都换算成路线坐标（沿线距离 s、横向偏移 d）写进 `route.json`。
- `src/route/types.ts` 增加对应的可选字段；`tests/data.test.ts` 增加格式校验。

**4b. 运行时：横断面和设施**
- `src/city/road/index.ts` 的 `crossSection`：某段有辅路时，主路外侧依次是路缘、侧分带（绿化和行道树）、辅路（沥青和标线，车开不进去）、人行道、绿化；没有辅路的段落保持现有的带状结构。左侧按对向车道外侧同样处理。
- 行道树（`src/city/props/trees.ts`）和路灯（`src/city/props/lamps.ts`）的行列移到侧分带上。
- 人行天桥：桥面、栏杆、两端楼梯，净空约 5.5 m，只做视觉，不参与碰撞。
- 公交站：候车亭道具。地铁出入口：小型雨棚道具。不使用真实的商标和标识。
- 建筑退让：`build_buildings` 的 `rightMargin`、`oppositeMargin` 和运行时的 `clearOfRoad` 改为按每一段的实际路宽计算，避免真实建筑和新增的辅路、人行道重叠。

**验收**
- 在科技园、世界之窗、车公庙、新洲路、CBD 绕行段各取一处，把俯视图和 OSM 底图、卫星图叠在一起对比：辅路和侧分带的位置大致吻合。
- 第 0 步的机位重拍，路边看起来像深南大道，而不是一条通用的城市道路。
- 圈速、撞墙判定的单元测试和冒烟测试全部通过，结果不变。

### 第 5 步：收尾和发布

- 性能：建筑恢复真实高度、行道树不再压低、新增建筑和道具都会增加三角面。用第 0 步的机位重测，目标是保持 60 FPS。如果超出，优先合并新道具的 draw call，或给远处建筑加简化层级。
- 测试：`npx tsc --noEmit`、`npx vitest run`、`npx playwright test` 全部通过。视廊相关的数据校验（`tests/data.test.ts` 里的 `viewCap` 检查）在没有 `clearZones` 时自然通过，确认后决定是否删除。
- 文档：
  - CHANGELOG 写逐项细节、校准结果和实测数据。
  - versions.md 增加 v0.5.0 一行和前后对比图，“关键指标”表增加“高度有数据依据的占比”和“虚构建筑数”两项。
  - `docs/osm-coverage.md` 更新高度来源表和覆盖率表。
  - `docs/asset-credits.md` 加入 CMAB 和 Overture 的署名。
- 打 `v0.5.0` 标签。

## 不在本版本范围

- **益田路、金田路的真实立交**：要做匝道和高程，路线几何和碰撞都得重写，改动远大于其他几项。
- **按路段变化的车道数**：OSM 标注的是 3–4 车道，但改变行车区宽度会影响碰撞、圈速和最佳成绩，留到确实需要时再做。
- **扩大场景**：网格分块加载、用 osm2streets 生成全路网、自由驾驶模式、地形。这些属于架构改动，适合作为 v0.6 单独规划。
- **深圳官方实景三维数据**：网格模型和 LOD1.3 需要以单位名义通过广东政务服务网申请（深圳市空间地理信息中心，23965967）。如果要用，可以现在就开始申请，和本版本并行，不阻塞。

## 需要人来做的事

数据下载、工具安装、代码、截图、测试和文档都由 agent 完成。下面这些 agent 做不了，或者需要你来判断：

**开工前**
- 不用做任何事。所有数据都是公开下载，不用账号。agent 会下载约 8 GB 的 CMAB 压缩包，并安装 `sevenzip` 和 `overturemaps` 两个工具，执行时会请你确认。

**第 1 步完成后：试玩一次**
- 开一遍全程，看两件事：
  - 地标被挡的程度能不能接受。特别是“世界之窗”和“平安金融中心”这两个以地标命名的检查点，到了那里如果完全看不到对应的地标，告诉 agent 是保留、改名还是挪位置。
  - 远景雾效恢复正常后，平安金融中心和京基100 在远处是否灰得太厉害。

**第 2、3 步完成后：看截图**
- agent 会给出前后对比截图。你比 agent 更清楚深圳实际长什么样，看看有没有明显不对的楼，比如住宅区里冒出一栋特别高的楼，或者熟悉的高楼变矮了。指出具体位置即可。

**第 4 步完成后：试玩一次**
- 确认驾驶手感、撞墙判定和之前一样；看辅路、天桥、公交站是否像深南大道。

**发布前**
- 最后试玩一遍，同意后由 agent 打 `v0.5.0` 标签。

**可选：申请深圳官方实景三维数据**
- 只有在打算以后用官方网格模型或 LOD1.3 时才需要。申请必须以单位（法人或其他组织，比如学校、实验室）名义，通过广东政务服务网“一般基础测绘成果提供使用”事项提交，个人和 agent 都办不了。咨询电话 23965967（深圳市空间地理信息中心）。v0.5.0 不依赖这份数据。
